# User guide: finite SMEFT calculation

The public entry point is `griffin::prediction::SMEFTCalculator`. It combines
Lisong's coefficient inputs with Jackson's finite prescription, using:

> GRIFFIN's NNLO+ SM form factors and mixed electroweak–QCD-extended
> scattering amplitude, with dimension-six corrections incorporated through
> a finite, unlinearized prescription.

Here **NNLO+** means NNLO plus the selected higher-order SM terms implemented
in GRIFFIN. **Finite** means evaluating the prescription at the requested
Wilson coefficients, rather than extracting a derivative at zero. The
nonlinear terms generated by that prescription are retained; this does not
mean that every possible higher-power SMEFT contribution is included.

This is the `smeft_v1.1.2` integration (CMake package version `1.1.2`).
For code migration and dated test
results, see [MIGRATION.md](MIGRATION.md) and
[REGRESSION_TEST_REPORT.md](REGRESSION_TEST_REPORT.md).

**Scattering scope:** the upstream v1.1.1 near-pole correction is included
in `mat_SMaas` and its interpolation grids. Exactly $s=M_Z^2$ remains
unsupported, and checks at selected inputs are not a general precision
Z-lineshape certification. Read the [correction and remaining limits](KNOWN_ISSUES.md#1-corrected-near-pole-background-and-remaining-exact-point-limit)
before using scattering predictions.

## Inputs

SM parameters belong to `SMval` (alpha scheme) or `SMvalGmu` (Gmu scheme).
All SM input access uses `InputPar`, for example
`sm.set(InputPar::ZMassExperiment, 91.1876)` and
`sm.get(InputPar::ZMassComplex)`. Particle/current arguments use `Fermion`
and `Current`, for example `Fermion::electron` and `Current::axial`.
These are the only supported label interfaces, including in the lower-level
SM classes: short macros and raw integer label overloads have been removed.
For the SM decay-width utilities in `<griffin/sm/tools.h>`, choose
`WidthScheme::ComplexPole` (the default) or `WidthScheme::RunningWidth`.

Wilson coefficients belong to a separate `smeft::Input`: they start at zero,
are real and dimensionless, and require an explicit positive Lambda in GeV.
Use named setters and `Generation::first/second/third` for flavor indices.
Replacing Lambda by `k*Lambda` and all coefficients by `k*k*C` leaves
the prediction unchanged. Supported coefficient families and validation
rules are listed in [the input conventions](SMEFT_IMPLEMENTATION.md#input-object-and-operator-coverage).

Coefficient input is currently supplied through C++ setters. Reading or
writing standard WCxf coefficient files is an optional file-exchange feature
that is not implemented; this does not remove any physics supported by the
C++ inputs. See [the explanation](KNOWN_ISSUES.md#2-finite-smeft-scope-and-coefficient-conventions).

## Using the merged API

The complete, compilable example is
[`examples/smeft_example.cc`](../examples/smeft_example.cc). Include the
public entry header, then fill the ordinary SM inputs as in that example:

```cpp
#include <griffin/SMEFT.h>

using namespace griffin;
// Construct and fill an SMvalGmu smGmu; see the complete example.
smeft::Input coefficients;
coefficients.setLambdaGeV(1000.0);
coefficients.setCphiWB(0.01); // dimensionless; C/Lambda^2 = .01 TeV^-2

prediction::ElectroweakSetup setup(EWInputScheme::GmuAlphaMZ, smGmu);
prediction::SMEFTCalculator calculation(setup, coefficients);
const Fermion initialFermion = Fermion::electron;
const Fermion finalFermion = Fermion::muon;
const double toPicobarns = 0.38937966e9;
prediction::ScatteringPoint point(initialFermion, finalFermion,
                                 90.0*90.0, 0.5, toPicobarns);
auto sigma = calculation.differentialCrossSection(point);
// sigma.smResult(), sigma.total(), sigma.modelCorrection(), all in pb
auto fv = calculation.pseudoObservable(prediction::PseudoObservable::FV,
                                      Fermion::electron);
```

The point contains the initial/final fermions, $s$ in GeV$^2$ (not the energy
$\sqrt{s}$), $\cos\theta$, and an output-unit factor. The factor
`0.38937966e9` converts GeV$^{-2}$ to pb; the returned cross section is
$d\sigma/d\cos\theta$. To scan energy, call the same calculator with a new
`ScatteringPoint` at each energy. Changing only the kinematics does not
require a new coefficient or mass solution.

For alpha use an `SMval` input and `EWInputScheme::AlphaMWMZ`. The calculation
owns snapshots of both SM inputs and coefficients, so later changes to the
caller inputs cannot change an existing result. Construct a new calculation
for each fit point. No pointers into a caller's temporary inputs are retained.

The example's `ZMassExperiment` and `ZWidthExperiment` setters supply the
running-width input convention. `SMval`/`SMvalGmu` convert those inputs to
the `ZMassComplex` and `ZWidthComplex` pole parameters. The prediction equations
and the exact-$s=M_Z^2$ restriction use that pole mass, not the unconverted
91.1876 GeV input. The WMass observable likewise returns the resolved W
pole mass; the Gmu solver also supplies its running-width counterpart.

Build and run from the project root:

```bash
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON -DGRIFFIN_BUILD_EXAMPLES=ON
cmake --build build/release -j 4
ctest --test-dir build/release --output-on-failure
./build/release/examples/smeft_example
```

The numerical regression uses Python 3's standard library only. Its fixtures
are bundled in the test directory. Neither original source repository nor
an internet connection is needed to rerun the tests from this working copy.

### Converting supplied amplitudes

For lower-level SM or SMEFT work, `<griffin/sm/tools.h>` provides a function
that converts already-computed amplitudes into $d\sigma/d\cos\theta$:

```cpp
#include <griffin/sm/tools.h>

// mVV, mAV, mVA and mAA are the four amplitudes at the same energy/angle.
const std::array<griffin::Cplx,4> amplitudes = {{mVV, mAV, mVA, mAA}};
double sigmaPb = griffin::differentialCrossSectionFromAmplitudes(
    amplitudes, griffin::Fermion::electron, griffin::Fermion::muon,
    90.0*90.0, 0.5, 0.38937966e9);
```

This applies the existing full angular square, color factor and unit conversion;
it does not compute amplitudes or add corrections. The supported final states
are muons, taus and $u,d,s,c,b$, with massless external kinematics. Inputs must
be finite, with $s>0$, $-1\leq\cos\theta\leq1$ and a positive unit factor.
The full calculator still excludes the two angular endpoints because of its
amplitude limitations. Ordinary SMEFT users can continue to call
`calculation.differentialCrossSection(point)` directly.

## Reading the result

| Method | Meaning for an observable $O$ |
|---|---|
| `smResult()` | $O(0)$: all Wilson coefficients zero, with the same prescription and a separate Gmu solve |
| `total()` | $O(C)$: the requested finite-coefficient prediction |
| `modelCorrection()` | $O(C)-O(0)$: the finite change, including the retained nonlinear dependence |

$O(C)$ denotes a function evaluated at $C$, not a claim that the answer is
first order in $C$. The finite change is neither a derivative at zero nor an
interference-only quantity. `FinitePrediction` has no inverse-scale order
labels.

`calculation.smInputValues()` returns the electroweak input values resolved
with all Wilson coefficients zero. In Gmu these include the separately solved
SM W mass; they are not a different collision energy or angle.
`calculation.smAmplitudes(point)` returns the four SM amplitudes at the same
requested scattering point. "SM" here includes the selected higher-order
SM contributions, not only tree level or an external benchmark.

## Contact inputs and importing Jackson benchmarks

For $e^+e^-\to\mu^+\mu^-$, the retained canonical-strength convention gives

$$
g_{LL}=C_{ll}^{1122}+C_{ll}^{1221},\quad
g_{RR}=C_{ee}^{1122},\quad
g_{LR}=C_{le}^{1122},\quad g_{RL}=C_{le}^{2211}.
$$

### Equivalent labels and setter behavior

For every generation tuple, Cll identifies the current-exchange pair
$prst\leftrightarrow stpr$. Thus $1122$ and $2211$ share one value, while
$1221$ and $2112$ share another; those two values remain independent.
Cee identifies the orbit $\{prst,stpr,ptsr,srpt\}$, using current exchange
and the four-dimensional same-chirality Fierz identity. In particular,
$1122,2211,1221,2112$ all name the same Cee value.

Each value is the total strength of one unique operator in this interface,
not a separately summed contribution for each spelling. Setters overwrite
that value: the latest assignment through any alias wins. Repeating an
assignment does not multiply the strength. No additional Hermiticity,
arbitrary index permutations or relations among other coefficients are
imposed. The pre-existing `Ceq`/reordered-`Cqe` alias is unchanged.

### Importing independent raw entries

To reproduce Jackson's four raw entries without changing physical strength,
first sum them outside the input object. The regression fixtures already
import them as

$$
C_{ll,L}^{1122}=C_{ll,J}^{1122}+C_{ll,J}^{2211},\qquad
C_{ll,L}^{1221}=C_{ll,J}^{1221}+C_{ll,J}^{2112},
$$

$$
C_{ee,L}^{1122}=C_{ee,J}^{1122}+C_{ee,J}^{1221}
+C_{ee,J}^{2211}+C_{ee,J}^{2112}.
$$

The Cle entries are unchanged and unrelated coefficients are zero. Each
canonical sum is assigned once; its alias getters then return the same sum.
Do not subsequently set an alias to zero or to one raw piece: that would
overwrite the imported total. Do not loop over all 81 raw tuples and set
unused aliases to zero. Start with a new zero-initialized `Input`, or call
`clearWilsonCoefficients()` to preserve Lambda while clearing coefficients;
then assign each unique strength once, after aggregating raw contributions.
The Gmu contribution is
$-\tfrac12 C_{ll,L}^{1221}
=-\tfrac12(C_{ll,J}^{1221}+C_{ll,J}^{2112})$, so the existing benchmark
normalization is preserved. No fixture values need to be rescaled.

This is an explicit conversion from Jackson's independently populated raw
entries, not summation performed by setters. No new public importer API is
provided. Existing already-canonical inputs need no change.

For example, migrate old independent values `Cll1221=a`, `Cll2112=b` to:

```cpp
const auto one = smeft::Generation::first;
const auto two = smeft::Generation::second;
coefficients.setCll(one, two, two, one, a + b); // assign the total once
```

Do not call `setCll(one,two,two,one,a)` followed by
`setCll(two,one,one,two,b)`: the second call replaces `a` with `b`; it does
not store `a+b`. Apply the same sum-once rule to the Cll current-exchange
pair $1122/2211$ and the four equivalent Cee labels when importing separate
raw contributions. See [SMEFT_IMPLEMENTATION.md](SMEFT_IMPLEMENTATION.md#contact-aliases-and-canonical-strengths)
for the precise supported identities.

## Exact prescription

The [implementation guide](SMEFT_IMPLEMENTATION.md#finite-prediction-equations)
contains the W-mass equation, FA/SW/FV formulas and complete
pole/background/contact decomposition. In practical terms:

- In Gmu, the W mass is solved separately at the requested coefficients and
  with all coefficients zero, re-evaluating SM Delta r at each mass iterate.
  In the alpha scheme, the supplied masses and widths are retained.
- Both calculations use the same NNLO+ SM form factors and `mat_SMaas`
  amplitude at their resolved inputs. There is no extra linear W-mass
  derivative.
- The explicit FA/SW additions are linear at fixed mass. The subsequent
  finite mass solution, pole construction and full square retain their
  generated nonlinear dependence.
- FV is constructed from FA and the effective mixing angle, including the
  existing SM imaginary-ratio term. Contact amplitudes are added once.

The mass solver is created automatically; ordinary users do not construct
`WMassSolution`. Its iteration count and residual are available through
`calculation.massSolution()`.

## SM accuracy and public class names

The public classes are defined directly as `ElectroweakSetup` and
`SMEFTCalculator`, in `include/griffin/sm/ElectroweakSetup.h` and
`include/griffin/smeft/SMEFTCalculator.h`. These are actual class names, not aliases.
See [MIGRATION.md](MIGRATION.md) for updating client builds and coefficient
inputs. Rebuild the library and its callers after a source-interface change.

`SMEFTCalculator` currently has **no selectable SM-order option**. It uses
the cumulative `FA_SMNNLO` and `SW_SMNNLO` form factors with `mat_SMaas`
for scattering; its Gmu solver uses `dr_SMNNLO`. The selected SM content
includes NNLO and selected three- and four-loop terms, not a uniform complete
order for every amplitude component. `mat_SMaas` includes the additional
mixed electroweak–QCD residue and off-resonance terms beyond the earlier
`mat_SMNNLO` comparison setup. The standalone FV physics formula is unchanged.

Consequently, current cross sections are not expected to reproduce the old
Jackson cross-section numbers unchanged. The archived fixtures remain
untouched: tests check the earlier assembly against that archive and the
current public result against a separately assembled `mat_SMaas` amplitude.
These checks share the underlying SM kernels and resolved mass inputs; they
are not an independent calculation of those kernels or a new Jackson
benchmark. See [the regression report](REGRESSION_TEST_REPORT.md).

There is no second calculation layer or hidden order selector. For SM-only
lower-level work, use the original SM classes directly; the retained programs in
[`examples/sm/`](../examples/sm/) demonstrate that interface. SM accuracy and whether SMEFT products
are retained are separate decisions.

### Headers and ownership

For a runnable, commented introduction to memory management, see
[`examples/sm/test_memory_management.cc`](../examples/sm/test_memory_management.cc).
Start at its `main()`: it prints when the actual `FV_SMLO` machinery creates,
copies and destroys instrumented FA/SW helpers. It demonstrates that moves
transfer the existing pair, assignment releases the old pair, and scope exit
cleans up even after a simulated error. A short input scan checks that live
helpers do not accumulate between iterations. The example-only tracing
classes do not change the SM formulas and are not needed by ordinary users.
Its counters cover the traced helpers, not every allocation in the process.

With the examples enabled as above, run:

```bash
./build/release/examples/test_memory_management
ctest --test-dir build/release -R '^test_memory_management$' -V
```

All 14 traced helpers must be destroyed at the end. This optional teaching
test supplements, rather than replaces, the more detailed ownership tests
in `tests/sm/`. Neither the SM inputs nor the counters are owned by an FV:
they must remain alive while helpers use them.

Ordinary clients need only `<griffin/SMEFT.h>`. The
[architecture guide](ARCHITECTURE.md) maps the more specialized headers to
their implementation files. The C++ namespace `griffin::prediction` is
not an additional engine or directory.

All headers now use explicit typed mass labels internally as well as in
client code. Including `SMval.h` no longer redefines mass labels or changes
the meaning of another header's inline formulas. There is no mass-label
include-order rule; the convenience header simply collects the usual interfaces.

`ElectroweakSetup` borrows its SM input: keep that object alive while
constructing the calculator. The calculator then owns copies of its SM
inputs and coefficients. Reuse it for different scattering kinematics;
construct a new one after changing input values or Wilson coefficients.

For direct SM-class use, FV objects now automatically release their owned
FA/SW helpers. Copying an FV duplicates those helpers at the same SM order;
changing the copy no longer changes the original's helpers. Both copies
still borrow their SM inputs, so keep those inputs alive.

The numerical-value `matel` constructor owns its four fixed form factors.
The constructor accepting existing form-factor objects borrows them instead:
keep those objects alive, and do not expect the matrix element to delete them.
Copies duplicate owned fixed values but continue to share externally borrowed
form factors. Moves transfer ownership; reassign moved-from objects before
using them. `setinput()` updates owned fixed form factors, not the external
borrowed ones. These rules also apply to `mat_SMNNLO` and `mat_SMaas`.

The repair follows the v1.2 ownership implementation only; no v1.2 scattering
prescription is imported. Rebuild the library and all clients because class
layouts changed. Custom form-factor subclasses should also follow the
[migration guidance](MIGRATION.md#sm-object-ownership).

## Scope and limitations

- Supported cross sections are massless electron annihilation to muons,
  taus and $u,d,s,c,b$. Bhabha, neutrino final states, scalar/pseudoscalar
  channels and collinear endpoint angles are rejected.
- Exactly $s=M_Z^2$ (pole mass) remains rejected despite the integrated
  near-pole correction. The checks cover their documented inputs, not
  arbitrary masses or vanishingly small offsets. Pole EWPOs remain available.
- WMass, FA, SW and FV are supported; SW for neutral fermions is rejected.
  The finite mass-equation shift is not a DeltaR observable.
- Missing/nonfinite inputs, invalid mass solutions, nonpositive FA and
  nonfinite results raise exceptions. These checks do not establish EFT
  validity for large coefficients or grid accuracy far from tested inputs.
- The result is partonic: no real-radiation integration, ISR convolution,
  beam model or detector treatment is supplied.

See [KNOWN_ISSUES.md](KNOWN_ISSUES.md) for the complete supported domain,
remaining lifetime/error-handling precautions and the exact-pole limitation.

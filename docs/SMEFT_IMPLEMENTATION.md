# SMEFT implementation and input conventions

The merged branch has one SMEFT prediction path:
[`prediction::SMEFTCalculator`](USER_GUIDE.md). It combines Lisong's typed
coefficient inputs with Jackson's finite mass prescription and full
cross-section square. Its SM content is the NNLO+ FA/SW form factors and the
`mat_SMaas` amplitude, including selected fermionic mixed electroweak–QCD
terms in both the pole residue and off-resonance background.

**In the Gmu scheme, the code solves for $M_W(C)$ by iteration and evaluates
the SM functions at that mass. It does not Taylor-expand their W-mass
dependence around the zero-coefficient mass $M_W(0)$.**

This document is the calculation and coefficient-convention specification.
[USER_GUIDE.md](USER_GUIDE.md) covers practical calls and input examples;
[MIGRATION.md](MIGRATION.md) lists changes for existing programs.

## Operator normalization and scope

$$
\mathcal L_{\rm SMEFT}=\mathcal L_{\rm SM}
+\sum_i\frac{C_i}{\Lambda^2}Q_i.
$$

Every stored coefficient is real and dimensionless; Lambda is supplied in
GeV. Equivalent Cll/Cee labels name a single canonical coefficient; they are
not separate summands in the Lagrangian. Its value is the total strength of
that unique operator in this interface. Direct vertices and local contact
amplitudes contain tree-level dimension-six insertions. The calculation
retains the nonlinear dependence generated by its
mass solution, pole construction and final square; it does not supply every
higher-power SMEFT term or a complete dimension-eight calculation. The
meaning of the result is therefore prescription-specific, not an all-orders
completion of the Lagrangian above.

## Input object and operator coverage

`smeft::Input` is separate from `inval`. It does not select an electroweak
scheme or calculate MW. Coefficients start at zero, while
`setLambdaGeV()` must be called explicitly before evaluation.

| Category | Stored coefficients |
|---|---|
| Bosonic | `CphiWB`, `CphiD` |
| Lepton currents | `Cphil1`, `Cphil3`, `Cphie` |
| Quark currents | `Cphiq1`, `Cphiq3`, `Cphiu`, `Cphid` |
| Four-fermion | `Cll`, `Clq1`, `Clq3`, `Clu`, `Cld`, `Cqe`, `Ceu`, `Ced`, `Cle`, `Cee` |

`Generation::first`, `second` and `third` are one-based flavor labels.
The API accepts all $3^2$ two-index and $3^4$ four-index label tuples, with
equivalent Cll/Cee labels sharing canonical storage as described below.
Storage does not imply that every coefficient contributes to the supported
flavor-diagonal observables. The container does not impose Hermiticity or a
flavor ansatz. Nonfinite coefficients, invalid generation indices and
nonpositive/nonfinite Lambda are rejected.

`Cqe` is the canonical spelling. `Ceq[p,r,s,t]` is an alias for
`Cqe[s,t,p,r]`, not another coefficient.

Complex coefficients, CP-odd directions, running, matching between scales
and RGE evolution are not implemented.

## Contact aliases and canonical strengths

For all generation labels, the supported operator identities are

$$
Q_{ll}^{prst}=Q_{ll}^{stpr},
\qquad
Q_{ee}^{prst}=Q_{ee}^{stpr}=Q_{ee}^{ptsr}=Q_{ee}^{srpt}.
$$

The first identity exchanges the two currents. Cee additionally uses the
four-dimensional same-chirality Fierz identity. The corresponding labels
share one coefficient value in the input API:

| Coefficient | Equivalent labels in the electron–muon example |
|---|---|
| Cll, first independent operator | `1122`, `2211` |
| Cll, second independent operator | `1221`, `2112` |
| Cee, one independent operator | `1122`, `2211`, `1221`, `2112` |

In particular, `Cee2211` accesses the same value as `Cee1122`.
The two Cll rows are **not**
aliases of one another. Do not extend the Cee Fierz identification to Cll:
the latter has weak-doublet contractions; see the [Warsaw-basis paper,
Eqs. (4.1)–(4.2) and Section 7](https://arxiv.org/html/1008.4884).
No extra Hermiticity relations,
arbitrary permutations or new relations for other coefficient families are
imposed.

Setters are assignments, not accumulators: the last write through any alias
wins, and every alias getter returns that value. To import independently
specified raw contributions, sum them first and set the canonical value once.
For example, independent entries `Cll1221=a` and `Cll2112=b` become

```cpp
const auto one = smeft::Generation::first;
const auto two = smeft::Generation::second;
coefficients.setCll(one, two, two, one, a + b);
```

Two sequential alias assignments would retain only the last value, not their
sum. Do not initialize/import by setting all 81 raw label tuples, including
zeros: a later zero alias would erase a nonzero canonical value. Start from a
zero-initialized `Input`, or call `clearWilsonCoefficients()` (which preserves
Lambda), then assign one value per unique operator. Aggregate independent
raw contributions before those assignments. Explicit Jackson benchmark
mapping is in [USER_GUIDE.md](USER_GUIDE.md#contact-inputs-and-importing-jackson-benchmarks).

## Input scheme and mass treatment

The scheme belongs to `prediction::ElectroweakSetup`:

- `GmuAlphaMZ` requires `SMvalGmu`/`invalGmu`. `WMassSolution` solves
  Jackson's finite mass equation separately for the SM input values (zero
  coefficients) and the requested coefficients, re-evaluating SM Delta r at each
  iterate. The supplied SM input is not mutated.
- `AlphaMWMZ` requires a directly supplied `SMval`/`inval`. The supplied
  masses and widths remain unchanged.

The Gmu combination $\Delta_\mu$ is defined in the equations below.
The canonical Cll strength is included once. Since `1221` and `2112`
access the same value, summing both getters would double-count it. With an
imported value $C_{ll}^{1221}=a+b$, this gives the combined
contribution $-(a+b)/2$.

The finite additive mass-equation displacement and solver conventions are
given in [Finite prediction equations](#finite-prediction-equations).
The resulting mass is supplied directly to the SM functions and direct
vertex shifts. This is how the W-mass change enters the observables.

`SMEFTCalculator` copies the SM inputs and coefficients. Later caller
mutations do not change an existing calculation; construct another calculator
for another fit point.

`SMEFTCalculator` and its observable types live alongside the coefficient
and matching interfaces in `include/griffin/smeft/`; implementation files live
in `src/smeft/`. The shared `EWInputScheme` definitions and `ElectroweakSetup`
class are together in `<griffin/sm/ElectroweakSetup.h>`. They pair a scheme
choice with ordinary SM inputs, without performing SMEFT matching.
The convenient umbrella remains `<griffin/SMEFT.h>`.
`<griffin/smeft/EWPO_smeft.h>` defines `PseudoObservable` and its name helper;
`<griffin/smeft/xsc_smeft.h>` defines `ScatteringPoint` and `CurrentChannel`
alongside the contact-amplitude interface. These request types belong to
the namespace `griffin::prediction`.

For SM-only mass solving, use the existing `SMvalGmu`/`invalGmu` input
classes. The finite SMEFT solution is available from
`SMEFTCalculator::massSolution()`; it does not modify the caller's SM object.

## Finite prediction equations

### W-mass solution in the Gmu scheme

Let $M$ denote the pole W mass and $M_Z$ the supplied pole Z mass. Define

$$
k=\frac{\pi\alpha}{\sqrt{2}G_\mu M_Z^2},\qquad
c_0^2=\frac12+\sqrt{\frac14-k},\qquad s_0^2=1-c_0^2,
$$

$$
\Delta_\mu=C_{\phi l,11}^{(3)}+C_{\phi l,22}^{(3)}
-\frac12C_{ll}^{1221},
$$

Here $C_{ll}^{1221}$ is the canonical total strength. The label $2112$
accesses that same value; it is not another term to sum in this equation.

$$
\delta x_6=-\frac{k}{2\sqrt{1/4-k}}
\frac{1}{\sqrt{2}G_\mu\Lambda^2}
\left[2\frac{c_0}{s_0}C_{\phi WB}
+\frac{c_0^2}{2s_0^2}C_{\phi D}+\Delta_\mu\right].
$$

The Gmu mass is found by iterating Jackson's equation:

$$
M_{n+1}^2=M_Z^2\left[\frac12+
\sqrt{\frac14-k\bigl(1+\operatorname{Re}\Delta r_{\rm SM}(M_n)\bigr)}
+\delta x_6\right].
$$

Here $\delta x_6$ is the dimensionless dimension-six input-matching term,
not the final shift $M_W(C)-M_W(0)$. It is linear in the Wilson coefficients;
the mass obtained by solving the equation is not restricted to that order.
The additive term is **outside** the square root, and
$\Delta r_{\rm SM}$ is evaluated again at every iterate.

The seed is 80 GeV and the default stopping
criterion is $|M_{n+1}^2-M_n^2|\leq10^{-4}\,{\rm GeV}^2$. As in Jackson's
code, the returned mass is the last evaluated iterate $M_n$, not the next
candidate. The iteration count and residual are available through
`massSolution()`. The solver enforces a configurable iteration limit and
physical-domain checks. The W width and running-mass/width values are
updated using Jackson's formula. In the alpha scheme the supplied
mass and widths are left unchanged.

### Pole observables at the solved mass

At that resolved mass, the fixed-mass direct vertex shifts are denoted
$\delta a_f(C,M)$ and $\delta v_f(C,M)$. Then

$$
F_A^f=F_{A,\rm SM}^{f,\mathrm{NNLO+}}(M)+2a_{f,0}(M)\delta a_f(C,M),
$$

$$
s_{\rm eff}^{2,f}=s_{{\rm eff},\rm SM}^{2,f,\mathrm{NNLO+}}(M)
-\frac{\delta v_f/a_{f,0}-v_{f,0}\delta a_f/a_{f,0}^2}{4|Q_f|}.
$$

These explicit additions are linear in the coefficients **at fixed $M$**.
In particular, the FA input does not include an explicit $(\delta a_f)^2$,
and the mixing-angle input uses the displayed first-order ratio shift,
not the exact ratio of shifted vector and axial couplings. This describes
the explicit dimension-six vertex insertions, **not** an approximation to
the W-mass dependence. In Gmu, every term in these expressions is evaluated
at the solved mass $M=M_W(C)$.

The functions
`smeft::directZAxialShift` and `smeft::directZVectorShift` compute only the
direct shift at the supplied mass. They have no input-scheme selector and do
not derive or shift MW. The calculator supplies the mass already resolved by
the mass resolver (`WMassSolution`), also in Gmu. It is created automatically;
ordinary callers do not need to include its header or construct it directly.

FV is constructed as

$$
F_V^f=F_A^f\left[(1-4|Q_f|\operatorname{Re}s_{\rm eff}^{2,f})^2+I_f^2\right],
\qquad
I_f=\frac{a_{f,0}\operatorname{Im}v_{f,1}
-v_{f,0}\operatorname{Im}a_{f,1}}{a_{f,0}^2}.
$$

Here $I_f$ is GRIFFIN's existing SM imaginary-ratio term, evaluated at the
resolved mass. Keeping it preserves the `FV_SMNNLO` construction when all
Wilson coefficients vanish. This same FA/SW-based construction is used for
nonzero coefficients.

### Scattering and the SM result

For each vector/axial channel,

$$
\mathcal A(C)=\mathcal A_{\tt mat\_SMaas}
\bigl(F_A(C),s_{\rm eff}^2(C);M(C)\bigr)+\mathcal A_{4f}(C).
$$

More explicitly, with $s_Z=M_Z^2-iM_Z\Gamma_Z$ and channel/angle labels
suppressed,

$$
\mathcal A(C;s)=
\frac{R_{\tt aas}\bigl(F_A(C),s_{\rm eff}^2(C);M(C)\bigr)}{s-s_Z}
+B_{\tt base}\bigl(s;M(C)\bigr)
+\delta B_{\tt aas}\bigl(s;M(C)\bigr)
+\mathcal A_{4f}(C).
$$

Here $R_{\tt aas}$ is the **complete** `mat_SMaas::coeffR()` residue,
not an extra correction to add to `mat_SMNNLO::coeffR()`.
$B_{\tt base}$ is `mat_SMNNLO::resoffZ()` and $\delta B_{\tt aas}$ is
`mat_SMaas::resoffZaas()`. The extension adds selected fermionic mixed
electroweak–QCD terms proportional to $\alpha\alpha_s$: additional imaginary
residue terms and energy-dependent photon/Z self-energy and photon–Z mixing
contributions. FA/SW already contain mixed electroweak–QCD corrections;
this is an additional amplitude-level contribution, not the first use of
$\alpha_s$ in the prediction.

The extension is evaluated at each calculation's resolved inputs for **both**
the requested-coefficient result and the zero-coefficient SM result. The
SM calculation repeats the Gmu mass solution with all coefficients set to zero;
it does not reuse the nonzero-coefficient W mass. In the alpha scheme both
evaluations use the same supplied W mass. At zero input $\alpha_s$, the
additional mixed electroweak–QCD scattering terms vanish.

The existing massless angular square is applied directly to these four
amplitudes. This includes SM–SMEFT interference, contact-squared terms and
vertex/contact products. Nonlinear dependence is also generated by the
finite Gmu solution and the pole/FV construction; it is not limited to a
single squared dimension-six amplitude. These generated terms do not supply
all higher-power terms of the SMEFT expansion.

## Direct Z-fermion shifts

`<griffin/smeft/ff0_smeft.h>` exposes

```cpp
double da = smeft::directZAxialShift(fermion, resolvedSM, coefficients);
double dv = smeft::directZVectorShift(fermion, resolvedSM, coefficients);
```

The `fermion` argument is a `Fermion` value; no integer overload is retained.
These functions return
only the direct tree-level dimension-six current shifts at the supplied
alpha, MW and MZ. They have no scheme selector and never change MW.
The calculator passes its already-resolved mass point to them.

The private particle lookup in `smeft::Input` identifies the generation and
category of electron/muon/tau, their neutrinos, up/charm, and
down/strange/bottom. Vertex and contact matching use that information to
select the supplied coefficients; unsupported species are rejected. The
lookup is declared privately in `SMEFTInput.h` and implemented in
`SMEFTInput.cc`, with no separate helper header or public lookup API.

The private helpers in `src/smeft/EWPO_smeft.cc` implement the FA/SW/FV
equations above, using the same resolved mass in every term.
The `FA_SMNNLO` and `SW_SMNNLO` classes include selected three- and
four-loop SM terms as well as NNLO; this is the meaning of NNLO+ here.
SW is undefined for a neutral fermion and is rejected.
The calculator exposes WMass, FA, SW and FV, but not a finite DeltaR
observable.

Both public observable requests and scattering pole inputs use that same
FA/SW evaluation.
Complete scattering-amplitude assembly remains in `SMEFTCalculator.cc`;
`xsc_smeft.cc` supplies only the local contact matching below.

## Local four-fermion matching

`<griffin/smeft/xsc_smeft.h>` exposes the standalone function
`smeft::fourFermionContactAmplitude(initial, final, initialCurrent, finalCurrent,
coefficients)`, with `Fermion` species and `Current` current labels only.
It returns the local reduced
contact amplitude, not a cross section or another SMEFT prediction
prescription. Its chiral coefficients are:

Every Cll/Cee entry below denotes its canonical total strength; aliases must
not be added again to these formulas.

| Final state of generation $i$ | $g_{LL}$ | $g_{LR}$ | $g_{RL}$ | $g_{RR}$ |
|---|---|---|---|---|
| Charged lepton, $i=2,3$ | $C_{ll}^{11ii}+C_{ll}^{1ii1}$ | $C_{le}^{11ii}$ | $C_{le}^{ii11}$ | $C_{ee}^{11ii}$ |
| Up-type quark | $C_{lq}^{(1)11ii}-C_{lq}^{(3)11ii}$ | $C_{lu}^{11ii}$ | $C_{qe}^{ii11}$ | $C_{eu}^{11ii}$ |
| Down-type quark | $C_{lq}^{(1)11ii}+C_{lq}^{(3)11ii}$ | $C_{ld}^{11ii}$ | $C_{qe}^{ii11}$ | $C_{ed}^{11ii}$ |
| $\nu_e$ contact only | $2C_{ll}^{1111}$ | $0$ | $C_{le}^{1111}$ | $0$ |
| $\nu_i$, $i=2,3$, contact only | $C_{ll}^{11ii}$ | $0$ | $C_{le}^{ii11}$ | $0$ |

The projection onto GRIFFIN's vector/axial convention is

$$
\begin{aligned}
4\Lambda^2\mathcal M^{4f}_{VV}&=g_{LL}+g_{LR}+g_{RL}+g_{RR},\\
4\Lambda^2\mathcal M^{4f}_{VA}&=g_{LL}-g_{LR}+g_{RL}-g_{RR},\\
4\Lambda^2\mathcal M^{4f}_{AV}&=g_{LL}+g_{LR}-g_{RL}-g_{RR},\\
4\Lambda^2\mathcal M^{4f}_{AA}&=g_{LL}-g_{LR}-g_{RL}+g_{RR}.
\end{aligned}
$$

The first current labels the initial state. This reduced contact amplitude
is independent of $s$, so no separate derivative function is needed. The
calculator adds it to the `mat_SMaas` amplitude once, then squares the full
amplitude. It is not added again as a separate Laurent term. The resulting
cross section still depends on energy through the scattering normalization
and the other amplitudes.

Both the requested-coefficient calculation and the zero-coefficient SM
calculation use the extended `mat_SMaas` residue/background at their own
resolved W masses. The extension changes the scattering amplitude, not
the contact matching, standalone FA/SW/FV formulas or finite Gmu equation.

## Cross-section scope

The function `differentialCrossSectionFromAmplitudes()`, declared in
`<griffin/sm/tools.h>` and implemented in `src/sm/tools.cc`, accepts four
amplitudes in the order `VV, AV, VA, AA` and applies the angular factors,
color multiplicity and normalization. It introduces no new amplitude
contributions; `mat_SMNNLO` and `mat_SMaas` remain the amplitude classes.
The calculator uses the function's full square, including SM–SMEFT interference,
contact-squared and vertex/contact products. Nonlinear terms also arise
through the pole construction and finite mass dependence, so the result is
not simply an SM cross section plus a squared dimension-six amplitude.

For every observable, `smResult()` is the independently evaluated
zero-coefficient SM result, `total()` is the requested-coefficient result, and
`modelCorrection()` is their finite difference. In Gmu the SM and
full results have separately solved W masses; in alpha both use the supplied
mass. The finite difference is not a derivative or an interference-only
quantity. See [the prediction equations](#finite-prediction-equations)
for the complete residue/background decomposition. `smInputValues()` returns
the zero-coefficient electroweak inputs, and `smAmplitudes(point)` returns
the corresponding four amplitudes at the requested energy and angle.

The selected mixed electroweak–QCD additions do not make the entire
off-resonance calculation complete at NNLO. They are evaluated with the
same resolved inputs as the rest of the amplitude, not as new SMEFT loop
amplitudes.

Supported complete processes are unpolarized electron annihilation into
muons, taus, or $u,d,s,c,b$, with external-fermion masses neglected in the
kinematics. This approximation does not remove masses from the SM loop
functions. Bhabha, all neutrino final states, non-electron initial
states and scalar/pseudoscalar requests are rejected by this interface.
Standalone neutrino contacts are not complete neutrino cross sections;
electron-neutrino production also needs t-channel W exchange.

The conversion function requires finite kinematics, $s>0$, a positive unit
factor and $-1\leq\cos\theta\leq1$. Its default unit factor is one, returning
GeV$^{-2}$. The full SMEFT calculator retains the stricter
$-1<\cos\theta<1$ restriction because its inherited amplitudes contain
endpoint singularities; a finite angular weight does not remove them.

The background includes the upstream v1.1.1 `zzhataas` and grid correction.
For $H(s)=\texttt{zzhataas}(s)$, $\Delta=s-M_Z^2$ and
$\Delta_0=10.01\,\mathrm{GeV}^2$, the near-pole branch uses

$$
H(s)=H(M_Z^2+\Delta_0)\left(\frac{\Delta}{\Delta_0}\right)^2,
\qquad |\Delta|<10\,\mathrm{GeV}^2.
$$

Consequently the AA self-energy background $-R_0H(s)/\Delta^2$ is constant
inside that window for nonzero $\Delta$; $R_0$ denotes the tree-level axial
coupling product. Exactly $s=M_Z^2$ remains rejected because the complete
background's limiting values have not been implemented. See
[KNOWN_ISSUES.md](KNOWN_ISSUES.md#1-corrected-near-pole-background-and-remaining-exact-point-limit).

## Verification

Current tests cover input conventions and contact aliases, fixed-mass direct
currents, local contacts, finite Gmu solutions, zero-coefficient SM limits,
full squares, scale rescaling, copy/lifetime behavior and
domain errors. Public-header and downstream-client checks cover the cleaned
interface and installation boundary.

The unchanged Jackson fixtures retain the previous `mat_SMNNLO` scattering
baseline. Tests compare a test-only reconstruction of that baseline to the
archive, and compare the extended public calculation to a separately
assembled `mat_SMaas` amplitude. These comparison assemblies share the SM kernels and
resolved inputs; this verifies the assembly and preserved matching, not an
independent derivation of the SM corrections. Current cross sections are
not expected to equal the historical baseline after the added SM terms.

```bash
./scripts/run_checks.sh
```

Run this command from the project root. The script builds the library and
examples, runs the tests and executes `smeft_example`. Independent upstream
near-pole constants are tested in `tests/sm/test_near_pole.cc`; manual SM
scattering formulas are compared with the helper and zero-coefficient
calculator in `tests/sm/test_scattering_equivalence.cc`. Earlier comparison
documents are archived outside this package, not mixed with current guides.

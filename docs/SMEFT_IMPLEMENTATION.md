# SMEFT implementation and input conventions

The merged branch has one SMEFT prediction path:
[`prediction::SMEFTCalculator`](USER_GUIDE.md). It combines Lisong's typed
coefficient inputs with Jackson's finite mass prescription and full
cross-section square. Its SM content is the NNLO+ FA/SW form factors and the
`mat_SMaas` amplitude, including selected fermionic mixed electroweak–QCD
terms in both the pole residue and off-resonance background. There is no
alternate linearized prediction path or SM-order selector.

This document describes the retained inputs and low-level matching.
[USER_GUIDE.md](USER_GUIDE.md) gives the complete prediction equations,
usage and migration instructions.

## Operator normalization and scope

$$
\mathcal L_{\rm SMEFT}=\mathcal L_{\rm SM}
+\sum_i\frac{C_i}{\Lambda^2}Q_i.
$$

Every stored coefficient is real and dimensionless; Lambda is supplied in
GeV. Equivalent Cll/Cee labels name a single canonical coefficient; they are
not separate summands in the Lagrangian. Its value is the total strength of
that unique operator in this interface. Direct vertices and local contact
amplitudes contain tree-level dimension-six insertions. The explicit vertex
and pole-input shifts are linear in the coefficients at fixed resolved MW.
The finite calculation retains the nonlinear dependence generated by its
mass solution, pole construction and final square; it does not supply every
higher-power SMEFT term or a complete dimension-eight calculation. The
meaning of the result is therefore prescription-specific, not an all-orders
completion of the Lagrangian above.

## Input object and operator coverage

`smeft::Input` is separate from `inval`. It does not select an electroweak
scheme or calculate MW. Coefficients start at zero, while
`setLambdaGeV()` must be called explicitly before evaluation.

| Category | Stored coefficients |
|---|---|
| Bosonic | `CphiWB`, `CphiD` |
| Lepton currents | `Cphil1`, `Cphil3`, `Cphie` |
| Quark currents | `Cphiq1`, `Cphiq3`, `Cphiu`, `Cphid` |
| Four-fermion | `Cll`, `Clq1`, `Clq3`, `Clu`, `Cld`, `Cqe`, `Ceu`, `Ced`, `Cle`, `Cee` |

`Generation::first`, `second` and `third` are one-based flavor labels.
The API accepts all $3^2$ two-index and $3^4$ four-index label tuples, with
equivalent Cll/Cee labels sharing canonical storage as described below.
Storage does not imply that every coefficient contributes to the supported
flavor-diagonal observables. The container does not impose Hermiticity or a
flavor ansatz. Nonfinite coefficients, invalid generation indices and
nonpositive/nonfinite Lambda are rejected.

`Cqe` is the canonical spelling. `Ceq[p,r,s,t]` is an alias for
`Cqe[s,t,p,r]`, not another coefficient. This pre-existing alias is unchanged.

Complex coefficients, CP-odd directions, running, matching between scales
and RGE evolution are not implemented.

## Contact aliases and canonical strengths

For all generation labels, the supported operator identities are

$$
Q_{ll}^{prst}=Q_{ll}^{stpr},
\qquad
Q_{ee}^{prst}=Q_{ee}^{stpr}=Q_{ee}^{ptsr}=Q_{ee}^{srpt}.
$$

The first identity exchanges the two currents. Cee additionally uses the
four-dimensional same-chirality Fierz identity. The corresponding labels
share one coefficient value in the input API:

| Coefficient | Equivalent labels in the electron–muon example |
|---|---|
| Cll, first independent operator | `1122`, `2211` |
| Cll, second independent operator | `1221`, `2112` |
| Cee, one independent operator | `1122`, `2211`, `1221`, `2112` |

In particular, `Cee2211` accesses the same value as `Cee1122`.
The two Cll rows are **not**
aliases of one another. Do not extend the Cee Fierz identification to Cll:
the latter has weak-doublet contractions; see the [Warsaw-basis paper,
Eqs. (4.1)–(4.2) and Section 7](https://arxiv.org/html/1008.4884).
No extra Hermiticity relations,
arbitrary permutations or new relations for other coefficient families are
imposed.

Setters are assignments, not accumulators: the last write through any alias
wins, and every alias getter returns that value. Existing canonical inputs
retain their normalization. To import independently specified old raw
contributions, sum them first and set the canonical value once. For example,
old independent `Cll1221=a` and `Cll2112=b` become

```cpp
const auto one = smeft::Generation::first;
const auto two = smeft::Generation::second;
coefficients.setCll(one, two, two, one, a + b);
```

Two sequential alias assignments would retain only the last value, not their
sum. Do not initialize/import by setting all 81 raw label tuples, including
zeros: a later zero alias would erase a nonzero canonical value. Start from a
zero-initialized `Input`, or call `clearWilsonCoefficients()` (which preserves
Lambda), then assign one value per unique operator. Aggregate independent
raw contributions before those assignments. Explicit Jackson benchmark
mapping remains in [USER_GUIDE.md](USER_GUIDE.md#contact-inputs-and-importing-jackson-benchmarks);
there is no new public importer API.

## Input scheme and mass treatment

The scheme belongs to `prediction::ElectroweakSetup`:

- `GmuAlphaMZ` requires `SMvalGmu`/`invalGmu`. `WMassSolution` solves
  Jackson's finite mass equation separately for the zero-coefficient
  reference and the requested coefficients, re-evaluating SM Delta r at each
  iterate. The supplied SM input is not mutated.
- `AlphaMWMZ` requires a directly supplied `SMval`/`inval`. The supplied
  masses and widths remain unchanged.

The Gmu input-matching combination is

$$
\Delta_\mu=C_{\phi l,11}^{(3)}+C_{\phi l,22}^{(3)}
-\frac12C_{ll}^{1221}.
$$

The canonical Cll strength is included once. Since `1221` and `2112`
access the same value, summing both getters would double-count it. With an
imported value $C_{ll}^{1221}=a+b$, this gives the unchanged old raw
contribution $-(a+b)/2$.

The finite additive mass-equation displacement and solver conventions are
given in [USER_GUIDE.md](USER_GUIDE.md#exact-prescription). This is the only
SMEFT W-mass treatment. No linear displacement, SM-response derivative or
additional induced mass correction is added to the vertices.

`SMEFTCalculator` copies the SM inputs and coefficients. Later caller
mutations do not change an existing calculation; construct another calculator
for another fit point.

`SMEFTCalculator` and its shared setup/observable headers live in
`include/griffin/`; implementation files live in `src/smeft/`.
`<griffin/Observables.h>` defines `PseudoObservable`, `ScatteringPoint` and
`CurrentChannel`. The namespace `griffin::prediction` is retained, but the
old directory and generic engine/provider framework are removed.

For SM-only mass solving, use the existing `SMvalGmu`/`invalGmu` input
classes. The finite SMEFT solution is available from
`SMEFTCalculator::massSolution()`; it does not modify the caller's SM object.

## Direct Z-fermion shifts

`<griffin/smeft/ff0_smeft.h>` exposes

```cpp
double da = smeft::directZAxialShift(fermion, resolvedSM, coefficients);
double dv = smeft::directZVectorShift(fermion, resolvedSM, coefficients);
```

Both integer and `Fermion` overloads are available. These functions return
only the direct tree-level dimension-six current shifts at the supplied
alpha, MW and MZ. They have no scheme selector and never change MW.
The calculator passes its already-resolved mass point to them.

The private flavor mapper in `src/smeft/detail/SMEFTFlavor.h` assigns electron/muon/tau,
their neutrinos, up/charm, and down/strange/bottom to their generations.
An unsupported species is rejected.

The calculator uses the direct shifts in

$$
F_A^f=F_{A,\mathrm{SM}}^{f,\mathrm{NNLO+}}(M_W)+2a_{f,0}\delta a_f,
$$

$$
s_{\mathrm{eff}}^{2,f}
=s_{\mathrm{eff,SM}}^{2,f,\mathrm{NNLO+}}(M_W)
-\frac{1}{4|Q_f|}
\left(\frac{\delta v_f}{a_{f,0}}
-\frac{v_{f,0}\delta a_f}{a_{f,0}^2}\right).
$$

All terms use the same resolved mass. The `FA_SMNNLO` and `SW_SMNNLO` classes
include selected three- and four-loop SM terms as well as NNLO; this is the
meaning of NNLO+ here. At fixed MW, the displayed additions are linear:
there is no explicit $(\delta a_f)^2$ in FA, and the mixing-angle shift is
not replaced by the exact ratio of shifted vector and axial couplings.
Evaluating these expressions at the finite Gmu mass $M_W(C)$ does not
linearize their mass dependence.

FV is constructed from those FA/SW values with the existing SM
imaginary-ratio term, not from a separate linear FV shift. SW is undefined
for a neutral fermion and is rejected.
The calculator exposes WMass, FA, SW and FV, but not a finite DeltaR
observable.

## Local four-fermion matching

`<griffin/smeft/xsc_smeft.h>` contains standalone contact functions
`coeffS4fD6Tree` and `coeffSp4fD6Tree`. They do not implement another
SMEFT amplitude prescription. Their chiral coefficients are:

Every Cll/Cee entry below denotes its canonical total strength; aliases must
not be added again to these formulas.

| Final state of generation $i$ | $g_{LL}$ | $g_{LR}$ | $g_{RL}$ | $g_{RR}$ |
|---|---|---|---|---|
| Charged lepton, $i=2,3$ | $C_{ll}^{11ii}+C_{ll}^{1ii1}$ | $C_{le}^{11ii}$ | $C_{le}^{ii11}$ | $C_{ee}^{11ii}$ |
| Up-type quark | $C_{lq}^{(1)11ii}-C_{lq}^{(3)11ii}$ | $C_{lu}^{11ii}$ | $C_{qe}^{ii11}$ | $C_{eu}^{11ii}$ |
| Down-type quark | $C_{lq}^{(1)11ii}+C_{lq}^{(3)11ii}$ | $C_{ld}^{11ii}$ | $C_{qe}^{ii11}$ | $C_{ed}^{11ii}$ |
| $\nu_e$ contact only | $2C_{ll}^{1111}$ | $0$ | $C_{le}^{1111}$ | $0$ |
| $\nu_i$, $i=2,3$, contact only | $C_{ll}^{11ii}$ | $0$ | $C_{le}^{ii11}$ | $0$ |

The projection onto GRIFFIN's vector/axial convention is

$$
\begin{aligned}
4\Lambda^2\delta S_{VV}&=g_{LL}+g_{LR}+g_{RL}+g_{RR},\\
4\Lambda^2\delta S_{VA}&=g_{LL}-g_{LR}+g_{RL}-g_{RR},\\
4\Lambda^2\delta S_{AV}&=g_{LL}+g_{LR}-g_{RL}-g_{RR},\\
4\Lambda^2\delta S_{AA}&=g_{LL}-g_{LR}-g_{RL}+g_{RR}.
\end{aligned}
$$

The first current labels the initial state. A local contact is independent of
$s$: its regular amplitude is $\delta S$, and its $\delta S'$ is zero. The
calculator adds it to `mat_SMaas` once, then squares the full amplitude.
It is not added again as a separate Laurent term.

Both the requested-coefficient calculation and the zero-coefficient SM
reference use the extended `mat_SMaas` residue/background at their own
resolved W masses. The extension changes the scattering amplitude, not
the contact matching, standalone FA/SW/FV formulas or finite Gmu equation.

## Cross-section scope

The shared `FermionPairCrossSection` helper, declared in
`<griffin/core/FermionPairCrossSection.h>`, defines the channel order
`VV, AV, VA, AA`, angular factors, color multiplicity and normalization.
The calculator uses its full square, including SM–SMEFT interference,
contact-squared and vertex/contact products. Nonlinear terms also arise
through the pole construction and finite mass dependence, so the result is
not simply an SM cross section plus a squared dimension-six amplitude.

For every observable, `reference()` is the independently evaluated
zero-coefficient result, `total()` is the requested-coefficient result, and
`modelCorrection()` is their finite difference. In Gmu the reference and
full results have separately solved W masses; in alpha both use the supplied
mass. The finite difference is not a derivative or an interference-only
quantity. See [the prediction equations](USER_GUIDE.md#exact-prescription)
for the complete residue/background decomposition.

The selected mixed electroweak–QCD additions do not make the entire
off-resonance calculation complete at NNLO. They are evaluated with the
same resolved inputs as the rest of the amplitude, not as new SMEFT loop
amplitudes.

Supported complete processes are unpolarized electron annihilation into
muons, taus, or $u,d,s,c,b$, with external-fermion masses neglected in the
kinematics. This approximation does not remove masses from the SM loop
functions. Bhabha, all neutrino final states, non-electron initial
states and scalar/pseudoscalar requests are rejected by this interface.
Standalone neutrino contacts are not complete neutrino cross sections;
electron-neutrino production also needs t-channel W exchange.

Exact $s=M_Z^2$ is currently rejected by the finite amplitude because the
inherited SM background has an unresolved numerical limit there. The physical
regular background is already included; the limitation is not a missing
separate $S$ contribution. See [KNOWN_ISSUES.md](KNOWN_ISSUES.md).

## Verification

Current tests cover input conventions and contact aliases, fixed-mass direct
currents, local contacts, finite Gmu solutions, zero-coefficient SM limits,
full squares, scale rescaling, copy/lifetime behavior and
domain errors. Public-header and downstream-client checks cover the cleaned
interface and installation boundary; no generic provider tests remain.

The unchanged Jackson fixtures retain the previous `mat_SMNNLO` scattering
baseline. Tests compare a test-only reconstruction of that baseline to the
archive, and compare the extended public calculation to a separately
assembled `mat_SMaas` amplitude. These references share the SM kernels and
resolved inputs; this verifies the assembly and preserved matching, not an
independent derivation of the SM corrections. Current cross sections are
not expected to equal the historical baseline after the added SM terms.

```bash
./scripts/run_checks.sh
```

Run this command from the project root. The script builds the library and
examples, runs the tests and executes `smeft_example`. Historical comparison documents remain
available as records of earlier prescriptions, not as current API examples.

# GRIFFIN

GRIFFIN (Gauge-invariant Resonance In Four-Fermion INteractions) is a C++
library for electroweak radiative corrections and fermion scattering near
and away from the Z resonance.

This `smeft_v1.2.2` integration combines Lisong's typed SMEFT inputs with
Jackson's finite prescription and the SM kernels from upstream `v1.2` at `ca2d523`.
`SMEFTCalculator` uses NNLO+ SM form factors and `mat_SMaas`, including its
selected fermionic mixed electroweak–QCD corrections. It resolves the requested
and zero-Wilson inputs separately, inserts dimension-six shifts, and retains
the nonlinear terms generated by the finite mass solution and full square.
See the [exact prescription](docs/USER_GUIDE.md#exact-prescription).

The additional `mat_SMNNLO2` class is available for direct SM calculations.
It is separate from the calculator's fixed `mat_SMaas` prescription, and its
disabled sectors prevent a claim of complete off-resonance NNLO coverage.

> **Collaborator review branch.** Precision Z-lineshape accuracy is not
> established. Exactly $s=M_Z^2$ remains unsupported, and `mat_SMNNLO2` has
> unresolved near-pole growth in its new box sector. Read the
> [limitations and diagnostics](docs/KNOWN_ISSUES.md#1-corrected-mixed-background-and-remaining-pole-restriction).

## Build and run

Requirements: CMake 3.20+, a C++11 compiler, and Python 3's standard library
for the default regression tests.

```bash
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release -DGRIFFIN_BUILD_EXAMPLES=ON
cmake --build build/release -j 4
./build/release/examples/smeft_example
./build/release/examples/testmatel2
ctest --test-dir build/release --output-on-failure
```

The two main examples demonstrate the
[finite SMEFT API](examples/smeft_example.cc) and
[upstream v1.2 SM amplitude](examples/testmatel2.cc).
`./scripts/run_checks.sh` builds, tests and runs the SMEFT example.

The five older SM demonstrations live in `examples/legacy/`, with executables
under `build/release/examples/legacy/`. Enable them independently with:

```bash
cmake -S . -B build/release -DGRIFFIN_BUILD_LEGACY_EXAMPLES=ON
cmake --build build/release -j 4
```

## Use from another project

Include `<griffin/SMEFT.h>` and link to `GRIFFIN::griffin`, either through
`add_subdirectory()` or an installed package:

```bash
cmake --install build/release --prefix /path/to/griffin-install
```

```cmake
find_package(GRIFFIN CONFIG REQUIRED)
target_link_libraries(my_program PRIVATE GRIFFIN::griffin)
```

External users should set `CMAKE_PREFIX_PATH` to that installation. Public headers
are under `include/griffin/`; implementations are under `src/`. SM formulas and
compiled tables live in `src/sm/expressions/` and `src/sm/grids/`.
External users need no runtime grid files.

## Testing

Run `ctest --test-dir build/release --output-on-failure` after the build above.
Tests run with `BUILD_TESTING=ON` (the default), independently of the example
options. They cover the finite mass solver, SMEFT matching and amplitudes,
public/installed interfaces, and these numerical references:

- [Historical Jackson and current assembly checks](tests/native_regression/README.md).
- [Independent upstream v1.1.1 comparison](tests/upstream_regression/README.md).
- [Independent upstream v1.2 comparison](tests/upstream_v12_reference/README.md).

The latest recorded run passed all 18 tests on 17 November 2026, including
[FV ownership](tests/test_fv_ownership.cc),
[matel ownership and allocation-failure cleanup](tests/test_matel_ownership.cc),
and [pole/running-width mass checks in both header orders](tests/test_typed_mass_indices.cc).
The ownership tests also pass AddressSanitizer/UndefinedBehaviorSanitizer;
explicit allocation/deallocation counts verify cleanup. Installed-package checks
pass, and all seven example outputs match their pre-repair outputs exactly. The earlier
[import audit](docs/history/REGRESSION_REPORT_2026-11-16.md) retains numerical
differences, tolerances and validation scope. Regression agreement does not
establish complete NNLO coverage or precision lineshape accuracy.

Scattering algebra and unit conversions are covered by `test_public_api`.
Dated result files are archived under `docs/history/validation/`; current
regression summaries are written into the build directory.

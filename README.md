# GRIFFIN — smeft_v1.1.1

GRIFFIN (Gauge-invariant Resonance In Four-Fermion INteractions) is a C++
library for electroweak radiative corrections and fermion scattering near
and away from the Z resonance.

The `smeft_v1.1.1` integration candidate (CMake package version **1.1.1**)
combines Lisong's typed SMEFT inputs with
Jackson's finite calculation. `SMEFTCalculator` uses GRIFFIN's NNLO+ SM
form factors and the `mat_SMaas` scattering amplitude, including selected
fermionic mixed electroweak–QCD terms in both the pole residue and the
off-resonance background. Dimension-six shifts enter this construction at
the resolved inputs; the complete amplitude is then squared.

The nonlinear terms generated by the finite Gmu mass solution, pole
construction and full square are retained. This is not a claim to include
every higher-power SMEFT contribution or complete off-resonance NNLO
corrections. The zero-coefficient SM result uses the same SM content and
input-solving procedure. There is one SMEFT prediction path and no public
SM-order selector.

## Start here

> **Near-pole update:** the upstream v1.1.1 `mat_SMaas` correction is now
> included in both the SM code and interpolation grids. The previously
> reported large near-pole artifacts belonged to the old kernel.
> Evaluation exactly at $s=M_Z^2$ remains unsupported. This is still a
> collaborator integration branch, not a blanket certification for precision
> Z-lineshape studies. See [the correction and remaining limits](docs/KNOWN_ISSUES.md#1-corrected-near-pole-background-and-remaining-exact-point-limit).

Build requirements: CMake 3.20 or newer and a C++11-capable compiler.

1. Read the [user guide](docs/USER_GUIDE.md) for inputs and result conventions.
2. Build and run [the complete SMEFT example](examples/smeft_example.cc).
3. Consult the [input/operator definitions](docs/SMEFT_IMPLEMENTATION.md)
   and [known limitations](docs/KNOWN_ISSUES.md) before a physics study.

```bash
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release -DGRIFFIN_BUILD_EXAMPLES=ON
cmake --build build/release -j 4
./build/release/examples/smeft_example
ctest --test-dir build/release --output-on-failure
```

Or run `./scripts/run_checks.sh` to build, test and run the SMEFT example.
The numerical regression requires Python 3's standard library; no external
Python packages are needed. See the [regression report](docs/REGRESSION_TEST_REPORT.md)
for recorded results and reproduction instructions.

New client code can include `<griffin/SMEFT.h>`. A CMake client links to
`GRIFFIN::griffin`, either after `add_subdirectory()` or through the installed
package:

```bash
cmake --install build/release --prefix /path/to/griffin-install
```

```cmake
find_package(GRIFFIN 1.1.1 CONFIG REQUIRED)
target_link_libraries(my_program PRIVATE GRIFFIN::griffin)
```

Point the client's `CMAKE_PREFIX_PATH` at that installation. See the
[migration guide](docs/MIGRATION.md) for adapting existing programs and
coefficient inputs. This integration branch is not an official published release.

## Where things live

| Directory | What it is for |
|---|---|
| `include/griffin/SMEFT.h` | Single convenience entry header for ordinary SMEFT use |
| `include/griffin/smeft/` | SMEFT calculator, observable types and coefficient/matching interfaces |
| `include/griffin/sm/ElectroweakSetup.h` | Shared electroweak scheme choices and pairing with ordinary SM inputs |
| `include/griffin/sm/`, `core/`, `numerics/` | SM, shared and numerical interfaces for lower-level use |
| `src/` | Implementation, grouped into core, SM, SMEFT and numerical routines |
| `src/sm/expressions/` | Analytic formula fragments compiled into the SM implementation |
| `data/grids/` | Retained interpolation tables; the selected tables are compiled into the library |
| `examples/smeft_example.cc` | Complete public-interface SMEFT example |
| `examples/sm/` | Retained SM demonstration programs |
| `tests/sm/` | SM near-pole and scattering-equivalence checks |
| Other `tests/` files | API, SMEFT, installation and frozen Jackson regression checks |
| `docs/` | Current guides, architecture, limitations and regression evidence |
| `cmake/`, `scripts/` | Build/install support and developer checks |
| `build/` | Generated build products, not source files |

The [architecture guide](docs/ARCHITECTURE.md) explains how these pieces
connect. All grid and test-source files are retained. Historical documentation,
dated run records and stale generated builds have been archived outside the
package; the current guides and test fixtures remain here.

The migrated `test_scattering_equivalence` checks the manual SM expressions,
the amplitude-to-cross-section helper and the calculator's zero-coefficient
limit. It is part of CTest whenever `BUILD_TESTING` is enabled:

```bash
ctest --test-dir build/release -R test_scattering_equivalence --output-on-failure
```

## SM library and reference material

The retained version 1.1 SM routines, with the upstream v1.1.1 mixed-background
code/grid correction, provide full NNLO and selected leading
higher-order contributions on the Z resonance, NLO plus selected mixed
electroweak/QCD corrections off resonance, and NLO Bhabha scattering. The
merged SMEFT calculator uses the fixed SM selection documented
in the [user guide](docs/USER_GUIDE.md#sm-accuracy-and-public-class-names);
the `mat_SMaas` extension is included. It supplements the amplitude-level
SM corrections without changing the FA/SW/FV insertion formulas or finite
Gmu mass equation. SMEFT Bhabha scattering is not supported.
Earlier Jackson cross-section fixtures use `mat_SMNNLO`; the tests retain
those historical checks separately from the extended-amplitude checks.
